# Mac・iPhone・iPadで状況を確認する

2026-11-12追加。処理担当は自宅のMac 1台、他の端末は閲覧・通知用です。

共通画面: https://pubmed-progress-thama.fairkayak3.chatgpt.site

## 使い方

- 職場のMac: 上のURLを開き、自宅と同じChatGPTアカウントでサインインします。リポジトリやPythonの準備は不要です。
- iPhone・iPad: SafariでURLを開き、共有メニューから「ホーム画面に追加」。追加したアイコンから開いてサインインし、「通知を有効にする」を押します。iOS / iPadOS 16.4以降が必要です。
- 「テスト通知」を押すと、自宅Macの次の同期時（通常約1分）に、その端末だけへテスト通知を送ります。Macアプリの起動とインターネット接続が必要です。
- 通知の解除は端末ごとに「この端末の通知を解除」。端末の通知設定・集中モードも通知表示に影響します。
- Macの既存アプリにも「共通の状況画面」ボタンを追加しました。表示されない場合はアプリを次回起動すると反映されます。

## 共有する内容

登録総数と6区分の件数、処理中の有無、処理担当Macの名前、最終確認日時、最新のJSON回収・保存完了の本数と日時のみです。PDF・論文JSON・PMID・タイトル・APIキー・予算情報は送りません。通知登録には各端末のWeb Push送信先・暗号化用公開情報を本人専用サイトへ保存します。

Macの既存台帳と同じ集計関数を読み取り専用で使用します。Cloud側はSitesの本人専用認証とD1を利用します。閲覧端末はデータを書き換えたり論文処理を実行したりできません。別のMacの空の台帳が自宅の状況を上書きしないよう、送信者は設定済みの1台に限定します。

Macアプリを開いている間、約1分ごとに状況を送信します。最終確認から5分以上経つと、古い情報であることを画面に表示します。Macアプリの終了・スリープ・停止中でも最後の状況は閲覧できますが、同期・通知送信は復帰後です。

**JSONの自動回収は従来どおり、Macアプリを開いて自動回収をオンにしている間だけです。** この共有処理は有料APIへの依頼、Batchの回収、画像生成、Notion登録を行いません。API側だけで完了していても、Macで回収・検証・保存が済むまで完了通知は送りません。「JSON作成・回収待ち」はAPIの実行中と回収待ちをまとめた件数です。

## 通知の条件と再試行

- API解析のattemptが `completed` になり、対応するJSONファイルが存在するものを対象とします。保存完了時刻はattemptのdetailsに `saved_at` として保存します。
- 初回は既存完了分を基準として記録し、過去の結果を通知しません。設定後に検出した完了のみが対象です。
- 1回の確認で新しく保存された複数本をまとめて通知します。API処理の完了と、Macへの保存完了を混同しません。
- 通信失敗時はローカルの送信待ち記録を残して再試行します。成功済み端末へは通常再送せず、失敗した端末だけを再試行します。送信成功直後・記録前に強制終了すると再送される可能性がありますが、通知には同じ識別タグを付けています。
- 送信先が失効（HTTP 404/410）した場合はその登録を削除します。未送信通知は7日で再試行を終了します。
- 初回配送時に通知登録端末がない場合は、その完了分を後から新規端末へ送りません。最新完了の表示は残ります。
- 配送受付は端末での表示を保証しません。実機の「テスト通知」で確認してください。

## 自宅Macの設定と停止

秘密情報はGit管理外の `.remote_status/` に保存します。ディレクトリは700、設定・秘密鍵は600です。バックアップ等で共有すると送信権限も引き継がれるため、このフォルダを職場のMacへコピーする必要はありません。

- `config.json`: 本人専用サイトのサービス用トークン、送信専用トークン、送信元ID・名前・公開鍵・秘密鍵パス。
- `vapid-private.pem`: 標準Web Pushの署名用秘密鍵。変更すると通知の再登録が必要です。
- `outbox.sqlite3`: 過去完了の基準・通知待ち・端末別配送記録。削除すると過去通知の基準が失われます。
- 通信失敗はアプリ画面に短く表示します。鍵やHTTP本文を出力しません。

依存追加: `.venv/bin/python -m pip install -r requirements-status.txt`

手動同期: `.venv/bin/python scripts/sync_status.py`

毎分の同期: 設定済みのMacアプリを起動すると自動で始まります。画面上部に「状況共有：同期済み」または再試行の表示が出ます。論文処理とは別スレッドで動き、通信失敗で回収処理を止めません。終了すれば同期も停止します。

Macアプリを閉じてCLIだけで回収した場合は、上記の手動同期を実行するか、次にアプリを開くと反映・通知されます。スリープ設定やOSのアクセス権限は変更しません。

試験したLaunchAgent方式はmacOSのDocumentsアクセス保護で実行できなかったため採用していません。作成した試験用LaunchAgentは解除しました。

既存の通知鍵を再生成しないよう、設定の再作成は拒否します。処理担当Macを変える場合は、元の同期を停止し、台帳・PDF・JSONと通知待ち状態を引き継いだうえで送信者設定を更新する別作業が必要です。2台同時の処理・双方向同期は対象外です。

## 費用・保守

独自ドメイン、有料通知サービス、追加のAI APIは利用しません。Web PushをMacから各ブラウザーの標準プッシュサービスへ直接送信します。Sitesの利用条件・契約に依存するため、永続的な無料を保証するものではありません。この実装では有料プランへの変更・契約は行いません。

サイトのソースは `status_site/`。軽量なWorkerとHTML/JavaScriptで、フレームワークやnpm実行時依存はありません。`npm run build` で `dist/server/index.js` を作成します。D1のスキーマは `drizzle/` の追記式マイグレーションで管理します。

Sites project: `appgprj_6af4efd43fa08191a0f9bddfffe0ccd7`。本人専用の公開範囲を維持してください。環境変数は `REPORTER_ID`、`REPORTER_TOKEN`（秘密）、`VAPID_PUBLIC_KEY`（公開）です。サービス用トークンはサイト認証の境界を通過するためMacだけで使い、ページ内やGitには含めません。

検証:

```sh
.venv/bin/python -m unittest discover -s tests
cd status_site
npm test
npm run build
```

関連公式資料: [AppleのWeb Push](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers)、[pywebpush](https://github.com/web-push-libs/pywebpush)。

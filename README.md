# PubMed GraRec Notion — 共通取り込み・OneDrive版

PDF → JSON → PNG → 確認・Notionへの登録を、PDF自動取得・JSONのBatch API・PNG確認後のNotion登録・手動作業・一括取り込みで進めます。完成した一式をまとめて取り込むこともできます。
**手動ルートはAPIキーなしで利用できます。JSONのBatch作成にはOpenAI APIキー、画面からのNotion登録にはNotion接続キーが必要です。自宅と職場のMacは、OneDrive上の同じファイルと進捗記録を使います。**

## 起動

`PubMed-grareko-notion.app` または `PubMedGraRecAuto.command` を開きます。`PubMedGraRec.command` も同じ画面を開きます。

アプリアイコンは `assets/app-icon.png` を使用します。別のMacで更新した場合も、`PubMedGraRecAuto.command` を開くとアイコンを含めてアプリが再作成されます。起動中のアプリへの反映には終了・再起動が必要です。

**別のMacで `.app` が見つからない場合**：`.app` とPython環境（`.venv`）はGit管理外のため、GitHubから同期してもコピーされません。各Macで次の準備を行います。

1. 初回は `SetupPaperPipeline.command` を開き、終了コードが `0` になることを確認します。Python環境を準備済みなら省略できます。
2. `PubMedGraRecAuto.command` を開きます。このMac用の `.app` を作成して起動します。作成にはmacOSのCommand Line Tools（`swiftc`）が必要です。
3. 以後は、このリポジトリ内の `PubMed-grareko-notion.app` を開けます。アプリは隣接するスクリプトとPython環境を使うため、`.app` だけを別のフォルダへ移動しないでください。Dockへ追加しておくと便利です。

起動後は「このMacの設定」で、このMacのOneDrive共通フォルダを指定してください。端末ごとの設定はGitHub経由では同期されません。

Macでは「論文処理のいま」が入口です。工程カードを押すと、その工程の論文と操作だけを表示します。iPhone・iPadの進捗画面は従来どおりです。区分は次の6つです。

- PDF取得待ち
- JSON作成待ち
- PNG作成待ち
- PNG確認・登録待ち
- 登録完了
- 要確認・競合

作業を休止する論文には、別に「再確認待ち」と「アーカイブ」を用意しています。「登録している論文」は両方を含む全件です。

### 不要になった論文・PDFを入手できなかった論文

- **対象から外す**：論文の操作欄から「長文のため」「関心がなくなった」「PDFを入手できなかった」などの理由（任意）を選んでアーカイブします。Batchの「予算・入力の確認待ち」の詳細からも操作できます。通常の工程一覧・API候補から外し、PMID・ファイル・検索履歴・完了記録は残します。ホームの「アーカイブ」で理由を確認し、「作業対象に戻す」で復帰できます。同じPMIDを再登録すると、アーカイブ中と案内します。
- **入手できず・再確認を延期**：PDF未取得の論文に、確認日・結果・次回確認日・補足メモを記録します。次回は今日から1か月後（翌月の同日、同日がなければ月末）が初期値で、画面で変更できます。日付は日本時間で扱います。
- PDF画面の **「今探す」「再確認待ち」** で切り替えます。確認結果と次回日付は一覧に常時表示し、待機中は次回確認日の早い順、期日到来後は「今探す」の先頭に表示します。期日の判定は起動・手動更新時です。「再確認日を変更」は前回の確認内容を保持し、「今すぐ再開」は待機を解除します。
- PDFを取り込むと再確認待ちは解除されます。アーカイブ中のファイル取り込みは復帰後に行います。送信済みAPI処理はアーカイブでは停止せず、後から回収した結果は記録の変更を検知して候補として保持します。期限到来による自動検索・自動課金は行わず、有料PDF検索の30日制限も維持します。
- 「保存ファイル・記録」の「手動確認・対象変更の履歴」で過去の判断を確認できます。記録はOneDriveで共有します。両方のMacで更新版を使い、同期後に「保存状況を確認」を押してください。

iPhone・iPadの既存進捗画面はアーカイブを除く件数を共有し、再確認待ちは「PDF取得待ち」に含めます。再確認日・理由の詳細はMac画面で確認します。

PDF自動取得と、画面で対象を確認して実行するJSONのBatch送信・回収を利用できます。選択・確認後のNotion登録も利用できます。API担当Macのアプリが起動中は送信済みBatchを自動回収します。教材HTML・原本PDFは論文ごとに選択してNotion担当Macから自動登録できます。PNGはWeb版ChatGPTで作成し、1枚ずつ確認して登録できます。PDF自動取得はPubMedと公開PDF配布元にアクセスし、JSON BatchはOpenAIへ選択したPDFと依頼文を送信します。形式確認、ファイルコピー、依頼文準備、進捗記録はローカルで行います。

## 共通フォルダを設定する

各MacでOneDriveに同じアカウントでサインインし、同じ専用フォルダ `PubMed_GraRec` を同期します。
アプリの「このMacの設定」で、そのMac上の共通フォルダの絶対パスと端末名を指定します。
初回のみ空の専用フォルダを作成します。職場では、先に自宅で作成した `workspace.json` が同期されたフォルダを選んでください。

自宅Macの例:

```text
~/Library/CloudStorage/OneDrive-個人用/PubMed_GraRec
```

端末名の例: `自宅 MacBook Air`、`職場 Mac`。ローカル設定はGit管理外の `output/manual_settings.json` に保存し、他のMacへコピーしません。

既存データがあるMacでは「このMacの旧台帳からファイルをコピー」を1回実行します。旧台帳の最新選択中のPDF・JSON・テーマ別JSON・PNG・依頼文を実ファイルとしてコピーします。共有側に登録済みのPMIDは上書きしません。旧台帳・旧版・元ファイルは元の場所に保持します。

CLIで同じ設定を行う場合:

```sh
.venv/bin/python scripts/setup_manual_workspace.py \
  --root "$HOME/Library/CloudStorage/OneDrive-個人用/PubMed_GraRec" \
  --device-name "自宅 MacBook Air" --copy-legacy
```

職場では初回に `SetupPaperPipeline.command` で環境を準備し、アプリで同じ共有フォルダを選択します。Gitで渡すものはアプリのソース、OneDriveで渡すものは論文ファイルと進捗です。

## 研究台帳から希望PMIDを受信

初回だけ、受信担当Macで「このMacの設定」→「研究台帳との連携」→「接続コードをコピー」を押し、台帳の「グラレコの受信Macを設定」に貼り付けます。普段は研究台帳で「入手希望」を保存し、「グラレコへ送る」を押してください。担当Macのアプリを次に起動したとき、新しいPMIDがOneDriveの共有フォルダに登録され、「PDF取得待ち」に表示されます。アプリを開いたまま受け取るには設定から「今すぐ受信」を押してください。受信失敗時も同じ操作で再試行できます。受信担当を変更する場合はOneDriveを同期してから、新しいMacの接続コードを登録します。

## 普段の操作

1. アプリを開くと共通フォルダ内に `00_取り込み待ち` と `01_取り込み済み` が作られます。既存のファイルを一括移動する必要はありません。
2. PubMed Abstractの希望PMIDのTXTを `00_取り込み待ち` に保存します。画面からのPMID入力・TXT選択も利用できます。PMIDだけの行、`PMID: 番号`、PubMed URLに対応し、重複は除きます。
3. PDFはPMIDの数字だけのファイル名（例: `41276263.pdf`）または `PMID_番号.pdf` で保存できます。PDF、Webで作った `PMID_番号.json`、`PMID_番号_テーマID.png`（例: `PMID_40522178_overview.png`）を `00_取り込み待ち` 直下に保存します。論文別フォルダの作成は不要です。任意のメモにはPMIDを記載します。どの端末からでも保存できます。PDFだけ、JSONだけ、完成した一式など、途中の工程から合流できます。JSONの取り込みには保存済み、または同時投入の本文PDFが必要です。
4. Macのホーム上部で **「取り込み待ちを処理」** を押すか、このリポジトリの **`取り込み・整理.command`** をダブルクリックします。アプリを開かずに `.command` だけで整理することもできます。共通の取り込み待ちは、起動や定期確認だけでは整理しません。
5. PDF→JSON→PNGの順に検証し、揃ったファイルから工程を判定します。途中の工程を1つずつ操作する必要はありません。成功した入力だけを `01_取り込み済み/取り込みID/` に移して保管します。元の相対フォルダ構成を保持し、既存の保管ファイルは上書きしません。
6. テーマごとに「画像と固定情報を照合」を開き、画像内のPMIDとPractice Changeを読み取って記録します。全テーマの承認後、「PNG確認・Notion登録」から登録します。手動でアップロードする場合は、論文一覧の「確認・登録の記録」で確認内容・登録先URL・完了チェックを記録します。メモに「作成済み」「登録済み」と書いただけでは完了にしません。
7. 端末を切り替える前に、OneDriveアプリでアップロード・同期の完了を確認します。

工程カードで専用画面に切り替えます。「登録している論文」は全PMIDの一覧で、各工程の一覧とともに検索・10本ずつのページ送りができます。「ホーム」で入口へ戻れます。取り込み待ちはファイル単位で別表示し、独立した「取り込み待ちを処理」ボタンで混在するPDF・完成JSON・PNGを整理します。件数は最終確認時のもので、必要に応じて「保存状況を確認」を押してください。整理結果と、残した入力の理由も表示します。

PDF画面では1論文に無料・有料の結果をまとめ、判定理由・確認先は詳細から開きます。取得済みを含む記録とCSVは「検索履歴・CSV」にあります。JSON画面ではAPI作成・回収とWebへの依頼を選べます。PNG画面の「PNG作成依頼をコピー」は依頼文と画像用データを含むJSONをコピーし、「保存ファイル名をコピー」でテーマ別の指定名もコピーできます。Web生成後の保存・取り込みは手動です。PNG確認・登録画面では、全画像と登録先の確認後にNotionへ送信します。API処理中・回収待ちへの入口は他の画面にも表示します。

同じ論文だけなら `00_取り込み待ち` へ直接一式を置くこともできます。JSON内のPMID、`PMID_番号` フォルダ、`PMID_番号_main.png` などのファイル名、PMID付きメモから対応を確認します。同じ場所に複数のPMIDがあり特定できないファイルは残します。複数論文もPMID付きのファイル名で直下に保存できます。PMIDごとのフォルダも引き続き利用できます。メモの自由文をAIで解釈する処理はありません。

同じファイルの再投入は既存として扱い、古い版を再採用しません。新しい候補が複数、PMID不一致、保存・同期直後、不正なファイルなどは入力を残します。古いPDF・JSONと新しい後続成果物の混在も保留します。入力を修正して再度「取り込み・整理」を実行してください。同じMacでアプリと `.command` が同時に動いた場合は、共有フォルダ単位で順番に処理します。別Macとの同期競合は従来どおり履歴に残し、要確認とします。

既存の論文別 `受け渡し/PDF`、`受け渡し/JSON`、`受け渡し/PNG` も利用できます。こちらはアプリ起動時、操作完了時、または「保存状況を確認」で確認・記録します。定期的な自動更新は行いません。共通取り込み待ちと論文別受け渡しへ、異なる候補を同時に置かないでください。

保存済みの版は変更せず、差し替えたファイルは新しい版として保存します。PDFの差し替えでJSON以降、JSONの差し替えでPNG以降の現行選択と完了状態を解除し、前の版は履歴に保持します。

### 登録済みの論文から教材一式を作る

1. ホームの **「教材作成」** で作成方法を選び、論文タイトルまたはPMIDで対象を選びます。
   - **既存グラレコJSONから要約教材を作る（初期選択）** は、共通フォルダに取り込み済みの論文全体のJSONを使います。記録済みの要約・結果・根拠と確認済みPNGからHTMLを作り、`教材/PMID_番号/既存JSON版/` に保存します。PDFの再精読や精読APIの利用はありません。
   - **PDFから教材用Master JSONを作る** は、章ごとの根拠を収録した詳細教材を作ります。原本に対応する検証済みの教材用Masterがあれば再利用し、なければPDFをAPIで精読・統合します。グラレコ用JSONのない論文にも使えます。
2. Notion登録の有無を選んで **「選択した論文の教材を作る」** を押します。既存JSON版と教材Master版は同じPMIDで両方作成でき、履歴で版を選んで開けます。登録を選ぶと、担当Macが同じ論文のNotionページに版ごとの見出し・HTML・原本PDFを追加します。旧記録にPDFがない既存JSON版ではHTMLのみを登録します。
3. PDF精読版で原本がなければ既存の無料検索を実行します。取得できない場合は、`papers/PMID_番号/受け渡し/PDF/` に原本を置くと、API担当Macが次の巡回で取り込みます。
4. 教材用Masterの新規作成ではAPI担当Macが原本を章に分け、抜粋PDFと依頼文を章別Batchに送ります。全章の引用と測定値を検証した後に全体統合を送り、学習版Master・オフラインHTML・原本PDF・PNG依頼JSONをOneDriveの `教材/PMID_番号/版ハッシュ/` に保存します。既存の費用台帳を全段階で共用します。申請済みの章と統合は同じ処理版で管理し、期間予算・残高・1版$4を予約時に判定します。教材作成画面の「依頼済み・作成済みの教材」に使用概算と未確定予約が表示されます。
5. 担当Macは起動時と起動中約3分間隔で未完了分を照合します。API担当とNotion担当が別なら各Macでアプリを起動してください。Notion登録を選んだ論文は、OneDrive同期後にNotion担当MacがHTMLと原本PDFを既存の照合手順で登録します。PNGは後から同じページへ追加できます。API担当は既存の予算設定、Notion担当は初回の手動登録で設定できます。
6. 予算や原本確認で保留になった場合は、表示理由を解消し、履歴から論文を選んで再度 **「教材一式を作る」** を押します。送信結果が不明な場合は元のBatchを照合します。原文に照合できない応答や目視確認が必要な引用は、表示された作業先で章別精読の再開手順を使って確認します。AIで生成した教材は医学的な人手確認を未評価として扱います。

履歴の「Notionページを開く」で各論文の登録先を確認できます。「個別設定を開く」では選んだ論文のPMIDを引き継ぎ、作成方法を切り替えてもう一方の版を追加できます。未登録の論文は「個別の教材を開く・作成方法を選んで依頼する」でPDF精読版を選び、PMIDを直接指定できます。作成済みの論文は履歴で選ぶと、次の操作ができます。

- **教材HTMLを開く** で図を操作し、各研究や実験条件から内包PDFの該当ページへ移動できます。
- 教材Master版では **PNG依頼JSONの場所を開く** で保存先を開き、`png-request-*.json` を従来どおりWeb版ChatGPTに渡せます。
- **教材HTMLと原本PDFをNotionへ登録** で、設定済みのNotionデータベースへ登録します。該当する論文ページを照合し、なければ作成します。HTMLは操作できる埋め込み、PDFは独立したPDFブロックになります。PNGが未作成でも利用でき、PNGの医学的確認・登録完了の状態は別に管理します。登録後は教材作成画面の「Notionページを開く」から確認できます。

**同じ教材ページへ、完成PNGを1枚ずつ追加する**

1. HTML登録後、教材作成画面の **「完成PNGを1枚ずつ確認・登録」→「完成PNGの保存先を開く」** から保存先を開きます。Web版ChatGPTで作ったPNGを、一覧のファイル名（例 `PMID_42526604_overview.png`）で入れます。このフォルダは教材版ごとにOneDriveで共有されます。
2. Notion担当Macで **「到着状況を更新」→「画像を確認して登録」** を押します。表示された画像をテーマの固定情報・原文と照合し、画像内のPMIDとPractice Changeを入力して **「このPNGを承認してNotionに追加」** を押します。各画像は教材ページの本文に追加され、教材作成画面に「HTML登録済み · PNG 1/5枚登録済み」と表示されます。
3. 次のPNGが届いたら同じ手順を繰り返します。送信中に終了した場合は、同じ担当Macで **「承認済みPNGの登録を再開」** を押します。承認時の画像とNotion側の添付を照合し、承認やアップロードの重複を防ぎます。結果不明の書き込みは照合待ちになります。

### Web生成後のPNGを照合する

WebへはMacの「PNG作成依頼をコピー」、または「依頼JSONの場所を開く」で作った最新の依頼を渡します。過去に書き出した依頼ファイルを使う場合は再出力してください。依頼にはテーマ別の元JSONと、対象・範囲・結果・推奨・限界・日本への適用を抽出した固定情報が入ります。数値は解析集団・評価項目・単位が書かれた原文と一緒に扱います。

| テーマの状態 | Macでの扱い |
| --- | --- |
| 作成待ち | Webで生成し、指定名で `00_取り込み待ち` に保存 |
| 医学的確認待ち | 「画像と固定情報を照合」でPNGを表示し、画像から読んだPMIDと評価を入力 |
| 不合格・再作成 | 表示された理由と固定情報を確認し、修正版を同じ保存名で再投入 |
| 承認済み | 全テーマの承認が揃うとNotion登録・手動登録の完了記録が可能 |

macOS標準のApple Visionが端末内でPNGを読み、識別できたPMID・Practice Changeの不一致を検出します。OCRは文字の誤認・見逃しがあり、一致しても自動承認しません。読めない部分がある場合は「閉じて保留」、画像に必要な記載が欠けている場合は「不一致・欠落のため却下」を選んでください。医学的な主題、群別数値・効果方向、推奨と確実性、未確認のAI提案、Take Home Message、日本語は人がJSON・原文と照合します。承認は画像とテーマJSONの両方の版に紐づきます。

取り込み済みフォルダには確認中・不合格の入力も保管します。完成品の判定にはMacの画面を使ってください。旧版で取り込んだ未登録のPNGも照合対象です。既に登録を完了した記録と既存PNGは保持します。複数のMacで取り込み・登録する場合は、各Macでアプリを更新して再起動してください。

### Webへ渡すファイルの見分け方

全文JSONを作る際に、問い・対象集団・主要結果・限界を一緒に読める単位でグラレコの枚数を決めます。長い論文でも焦点が一つなら1枚、対象や治療段階で条件が変わる場合は関連する問いをテーマ図2〜4枚にまとめることを目安にします。重要な条件や例外を保つため5枚以上が必要なら増やし、理由を示します。例えば3テーマの関係を示す全体図が必要なら、全体図1枚＋テーマ別3枚で計4枚です。「PNG作成待ち」で合計枚数を確認し、各図の依頼をコピーしてWebで1枚ずつ作成します。更新後に取り込んだ全文JSONでは各図の題名と構成の理由も表示します。

| 用途 | ファイル名の例 | Webへ渡すもの／完成物 |
| --- | --- | --- |
| PDFから全文JSONを作る依頼 | `PMID_40522178_JSON作成依頼_PDF添付.txt` | このTXT＋本文PDF → `PMID_40522178.json` |
| テーマのPNGを作る依頼 | `PMID_40522178_overview_PNG作成依頼.json` | このJSON1個（依頼文・描画ルール・画像用データを内包）→ `PMID_40522178_overview.png` |
| 全文JSONの完成データ | `PMID_40522178.json` | `00_取り込み待ち` 直下へ保存し「取り込み・整理」 |

一覧の「JSON作成依頼TXTの場所を開く」「PNG作成依頼JSONの場所を開く」で、現在のデータから依頼を準備しFinderで選択表示します。旧記録でも利用でき、元のPDF・JSON・PNGや完了状態は変更しません。依頼文をコピーしてWebへ貼り付ける方法も利用できます。PNG作成依頼JSONは完成データではないため、取り込み待ちに入れると案内を表示して残します。

通常のPNG作成ではPDFの再添付は不要です。JSONの内容を原文と照合・訂正する場合は、PDFとJSONの両方が必要になることがあります。旧 `master.json` や `40522178_master.json` も引き続き取り込めます。ファイル名を変えるだけで形式を変換する必要はありません。

JSONは従来の `hybrid-v1` Master JSON形式です。自由形式のJSONや画像用JSONだけを新しい全文JSONとして取り込むことはできません。依頼文に必要なSchemaが含まれます。構文・対応の検証は医学的正確性の保証ではありません。

JSONの形式と論文・原本との対応は正しくても、テーマへの推奨割り当て漏れや章IDの不整合がある場合は、一覧に **「生成済み・構造確認待ち」** と表示します（上部の「要確認・競合」に集計）。生成されたJSONはDRAFTファイルとして履歴に保持し、理由と該当IDを表示します。修正したMaster JSONを受け渡しのJSONフォルダに保存すると再検証し、合格後にテーマ別PNG作成へ進めます。以前の版が残っていても、構造確認待ちの間は画像依頼文のコピーを止めます。

2026-11-13に生成指示を改善しました。参照する小節・図表を章一覧に登録し、IDの完全一致と全結果・全推奨の割り当てを出力前に確認するよう指示します。ローカルの整合性検証も引き続き行います。

## PDFを自動取得する（段階3）

1. アプリを終了して再起動し、先にPMIDを登録します。希望PMIDのTXTを取り込み待ちに置いた場合は「取り込み・整理」を実行してください。
2. 工程「PDF取得待ち」の **「自動取得」** を押します。論文一覧の **「PDF自動取得」** から1本を選ぶこともできます。
3. 対象をチェックし、**「選択した論文のPDFを取得」** を押します。最大50本を順番に処理し、処理中のPMIDと進行状況を表示します。ボタンを押していない論文を自動取得することはありません。
4. PDFの構造を検証し、先頭ページのタイトルとDOIまたはPMIDを照合します。一致した本文PDFは `papers/PMID_番号/files/内容ハッシュ/PMID_番号.pdf` に保存し、JSON作成待ちへ進めます。Web用のJSON作成依頼文も準備します。OneDriveクラウドへのアップロード完了はOneDriveアプリで確認してください。
5. 取得結果の各論文を開くと、理由・保存したPDF・手動確認先を確認できます。未取得分はPDF取得待ちのままです。再試行する場合は対象を選び直してください。

検索処理は既存の `pubmed-pdf-fetcher` の `PdfFinder` を再利用しています。PMC、Unpaywall、Europe PMC、出版社の公開リンク・PDFメタデータを順番に確認します。別の `pubmed-pdf-fetcher` リポジトリの配置は不要です。`scripts/paper_pipeline/pdf_finder.py` は同リポジトリの `92831f7` から取り込み、PDFを名乗るHTML応答を除外する先頭バイト確認を追加しました。書誌取得には既存の `pubmed.py` を使います。追加の依存ライブラリはありません。

AI APIキーは不要です。Unpaywallは実行環境の `UNPAYWALL_EMAIL` が設定されている場合だけ使い、未設定なら他の検索先へ進みます。NCBIの任意の `NCBI_EMAIL`・`NCBI_API_KEY` も既存の処理に従います。`.env` は読み込みません。OpenAI・Notion APIは呼び出しません。

- 本文と書誌情報の一致を確認できないPDFは「PDF候補・要照合」として同じ共有フォルダへ保管し、PDF取得待ちを維持します。原本を確認し、正しい本文PDFなら `00_取り込み待ち/PMID_番号/` へコピーして「取り込み・整理」で採用してください。構造不正・暗号化・49MiB超のPDFは自動採用しません。
- 取得済みのPDFや後続のJSON・PNGは置き換えません。手動保存したPDFが取り込み待ち・受け渡しにある場合は、先にそちらを整理します。
- 通信中は共有フォルダのロックを保持せず、保存前に記録の版を再確認します。別端末で更新された場合は取得PDFを候補として保管し、既存の記録を上書きしません。
- 認証・CAPTCHA・所属機関ログインが必要な論文は、取得結果の「手動確認先を開く」で標準ブラウザーへ引き継ぎます。
- 処理中はMacのアプリを開いておいてください。中断後は保存済み分を保持し、次回は未取得の論文を選んで実行します。起動時・定期確認時の自動ダウンロードはありません。

前回の結果は端末ごとの `状況/端末ID/PDF取得結果.json`、実行ごとの履歴は `PDF取得履歴/実行ID.json` に残します。結果の画面表示はこのMacの前回分です。論文ファイル・工程記録はOneDrive経由で他の端末にも共有されます。iPhone用の既存サイトには従来どおり工程件数だけを共有します。

## レビューや長い論文を読む

- PMIDを手入力で登録したときと、アプリでPDFを検索したときにPubMedの書誌情報を取得します。論文一覧には「レビュー」「システマティックレビュー／メタ解析」などの種別を表示します。既存の論文や台帳から受け取った論文も、**「読書ガイド・テーマ図解」→「PubMed書誌・抄録を取得」** で確認できます。種別が未確認の論文も作業対象です。
- **「読書ガイド・テーマ図解」** ではPubMedの原文抄録と、取得できたPDFのしおりを確認できます。**「短い読書ガイドの依頼をコピー」** を押してChatGPT Webへ貼り付けると、参照範囲を明示した短い読書ガイドを依頼できます。この操作はPDFの添付が不要です。全文JSONを取り込み済みの場合は一行要約も表示します。
- 問いが一つのシステマティックレビューは通常のJSON・PNGの手順を使えます。テーマが広い論文は読書ガイドで読む箇所を絞り、関心のあるテーマだけ文章や図で整理できます。原本PDFのページ番号で関連する方法・結果・図表・限界を合計12ページまで選び、出力形式を指定して **「抜粋PDFと依頼文を保存」** を押します。抄録やしおりがない論文にも使えます。保存した2ファイルをChatGPT Webへ添付し、PMIDと参照ページを明記した文章や部分図解を依頼します。部分図解の完成画像は開いた保存先に保管します。この図解は個人の読書用で、アプリの全文JSONやNotion登録の工程には入りません。

## 精読JSONをオフラインで読む

Macの論文一覧で、完成JSONのある論文の **「オフラインReaderを開く」** を押します。ブラウザで、概要、主要結果と図表、出典、限界、外来への示唆を読めます。目次から移動でき、検索すると一致したセクションが展開されます。印刷時には全文を表示します。PNGは現在のJSONに対応する確認済みの画像を埋め込みます。未取得・未同期・確認待ちのPNGがあっても本文を開けます。

旧ChatGPT精読JSONや、別に保存したJSON・PNGはCLIから指定できます。次の例はリポジトリのルートで実行します。

```sh
.venv/bin/python scripts/generate_reader.py input/chatgpt_summaries/done/42557795.json \
  --png images/2026/08/PMID_42557795_grarec.png
```

表示されたパスの `reader.html` を開いてください。画像は任意で、複数ある場合は `--png` を繰り返します。CLIでは対応する版の画像を自分で選びます。ファイル名・PMIDフォルダから分かる他論文の画像はエラーになります。出力先の親フォルダは `--output-dir` で指定できます。

標準の保存先はこのMacの `output/readers/PMID_<番号>/<HTMLのSHA-256>/reader.html` です。同じ入力・テンプレートなら同じファイルを使い、更新後は別の版を保存します。PNG・CSS・検索用JavaScriptはHTMLに含まれるため、1ファイルをコピーしてオフラインで閲覧できます。生成はローカルで完結し、原本・OneDriveの工程記録・Notionへの書き込みはありません。

旧形式は文字列・配列・図表の辞書をそのまま読める形に整えます。現行の `hybrid-v1` はテーマと対応する原文位置・根拠を表示します。Readerは `schemas/learning-v2.json` に適合したファイルもCLIから読み、章・抄録対訳・構造化された数値を表示します。原文抄録はJSON又はMacに保存済みのPubMed書誌を使い、訳は保存済みの場合だけ表示します。未取得の情報は「未取得」、未評価のPractice Changeは「未評価」と表示します。

## 長文のレビューやガイドラインを章別に精読する

ローカルCLIでPDFの章・節ごとに資料を準備し、戻ってきた精読結果を順次取り込めます。原本は読み取り専用です。作業先はこのMacの `output/chapter_reviews` で、OneDriveの進捗・Notion登録とは独立しています。

**1. PDFを分割する。** リポジトリのルートで次を実行します。最後に表示される作業フォルダを控えてください。PDFに書誌タイトルがない場合は `--title` で指定します。`--journal`、`--year`、`--doi` も任意で指定できます。

```sh
.venv/bin/python scripts/review_chapters.py prepare \
  'input/pdfs/42526604_Use electronic cigarettes asthma across lifespan.pdf' \
  --pmid 42526604 --article-type narrative_review
```

`manifest.json` に分割方法、各章の見出し、階層、原本の開始・終了ページを記録します。しおりや本文の見出しを使い、長い節は既定で10ページ・抽出文字数32,000字を目安に分けます。1ページは分断しません。見出しを検出できないPDFはページ範囲に分割します。自動判定を直す場合は `--sections sections.json` を付けて再準備してください。分割計画が変わると別の作業フォルダになります。

```json
[{"title":"Introduction","page":1},{"title":"Recommendations","page":8},{"title":"Exceptions","page":9,"level":2}]
```

`page` は表紙を1とする原本PDFの物理ページです。同じページに複数の節を指定できます。境界がページの途中にある場合、両方の抜粋にそのページを残します。抽出テキストで見出しを特定できた箇所は節内に絞って引用を照合します。スキャンや不規則な組版では原ページの見出しを確認してください。

**2. 章ごとに精読する。** 各 `ch0001` 等のフォルダには抜粋 `source.pdf`、精読依頼 `request.txt`、記入用 `response-template.json` が入ります。人が記入する場合は雛形をコピーして `response.json` として保存します。既存のWeb手動運用なら抜粋と依頼文から得たJSONを同じ名前で保存します。CLIからPDFや依頼文を外部に送る処理はありません。

新規の分割は医師向け教材形式（`chapter-learning-v2`）を使います。従来形式の新規作成には `prepare --classic` を指定できます。既存作業フォルダは保存した形式で再開します。

結果には章の日本語解説、所見の種類・適用条件・例外、出典ページと原文の短い引用を記入します。`source_numbers` はその章の `sources` 配列の1番目から数えます。測定値は `measurements` に原文表記を保存します。`highlight: true` の所見は全体統合の候補です。研究結果には `study` に文献・デザイン・対象・曝露・アウトカムを記録します。表と本文の同じ解析には同じ `result_key` と研究情報を指定し、集団やアウトカムが異なる解析は分けます。表紙や文献一覧は章の位置を示す引用を添え、所見を空にできます。

**3. 取り込み・再開する。** `prepare` が表示したフォルダを指定します。

```sh
.venv/bin/python scripts/review_chapters.py resume '作業フォルダのパス'
```

`pending` は未提出の章、`errors` は修正が必要な章と理由です。一部の章にエラーがあっても、他の正常な章を受理します。未完了分を保存して同じコマンドを実行すると、受理済みの `accepted.json` を再利用します。終了コードは完成が0、未提出が1、エラーが2です。

図表やスキャンの引用を文字抽出で確認できない場合は、該当出典に `visual_only: true` を記録し、原ページと目視照合したうえで `resume … --confirm-visual ch0003` のように章を指定します。確認方法はMasterに残ります。受理済みの章を訂正する場合は、その章の `response.json` を直して `--revise ch0003` を指定します。

**4. 全章の内容を統合する。** 教材形式では全章の受理後にいったん終了コード1を返し、`synthesis` に統合用フォルダを表示します。その中の `request.txt`、`context.json`、`schema.json` と原本PDFを使って `response.json` を作成し、同じフォルダに保存してください。章の受理内容や統合仕様が変わると、別の統合用フォルダが選ばれます。`master-schema.json` に最終教材のスキーマも出力します。

統合担当者は全章を確認し、overview各項目の根拠または欠測状態、原文抄録の逐語断片と対訳、外来へのAI解釈、学習単元、必要な図解を指定します。`units` には日本語の題名と章IDを指定し、`evidence_ids` を併用すると複数の処理章から一つの医学的テーマを構成できます。`forest_plot` では原文が報告した比と95% CIを使い、指標・集団・デザインごとにパネルを分けます。

**5. 教材と画像用データを保存する。** 再度 `resume` を実行します。対応を確認した既存PNGと原本PDFを内包する場合の例です。どちらも省略できます。

```sh
.venv/bin/python scripts/review_chapters.py resume '作業フォルダのパス' \
  --png images/2026/08/PMID_42526604_grarec.png \
  --pdf 'input/pdfs/42526604_Use electronic cigarettes asthma across lifespan.pdf'
```

`editions` に教材の `master.json`（learning-v3）、単体でオフライン閲覧できる `reader.html`、既存PNG経路に取り込める `png-master.json`（hybrid-v1）、各テーマの `png-request-*.json` を保存します。HTMLのページ表記から根拠を展開でき、原本を内包した場合は該当ページへのリンクも使えます。PDFビューアによっては先頭ページで開くため、物理ページ番号も表示します。教材を単独で再描画するときは `scripts/generate_reader.py` に版を指定できます。

研究別グラフだけを開くには、`forest_plot` を収録した学習版Masterを次のように指定します。

```sh
.venv/bin/python scripts/generate_reader.py path/to/master.json --study-plots --pdf path/to/original.pdf
```

表示されたパスの `reader_study_plots.html` を開きます。点を選ぶと、その測定値の報告値、引用、研究詳細を表示します。`--pdf` を付けると、SHA-256を照合した原本の該当ページをオフラインで開けます。

候補機序の分岐を確認するには、`mechanism_diagram` を収録した学習版Masterで次を実行します。

```sh
.venv/bin/python scripts/generate_reader.py path/to/master.json --mechanisms --pdf path/to/original.pdf
```

出力された `reader_mechanisms.html` では、起点から伸びる各分岐を直接選ぶか、「次の所見へ」で順に閲覧できます。各研究の「条件・根拠・原文」から、実験条件・限界・引用と該当ページを確認できます。

**6. 品質を評価する。** `resume` の `assessment` と `quality` に8項目の状態が出ます。評価を記録するには表示された `quality_template` を同じディレクトリの `response.json` にコピーし、確認した項目だけ状態・評価者・確認内容を記入して同じ引数で再開します。評価は画像・原本の添付と描画結果を含む版に紐づきます。機械的な引用一致やPNG形式の合格を医学的な承認に使いません。`--classic` および以前に準備した従来のrunは、全章受理後に従来のMasterとReaderを生成します。

## Batch APIでJSONを作成・回収する（段階4）

1. アプリを再起動し、工程2の **「APIでJSON作成・回収」** を開きます。API操作は担当Mac 1台に限定します。手動取り込みやPDF取得は他のMacでも続けられます。
2. 担当Macのリポジトリ直下の `.env` に `OPENAI_API_KEY=...` を設定します（既存のキーを利用可能）。環境変数があれば優先し、`.env`からはこのキーだけを読みます。キーをOneDriveへ置いたり、画面やチャットへ貼ったりする必要はありません。
3. **「APIキー・担当Mac・予算の設定」** で購入済み残高、他の処理の使用・予約額、予算期間の終了日と残高有効期限の早い方を入力します。期限はUTC日付の開始時刻です。自動チャージ無効と旧Batch等の未精算分を確認し、保存します。設定は最初の1台だけで行い、OneDrive同期後に他のMacを開いてください。
4. Batch候補の一覧でPMID・論文名・種別を確認します。**「PubMedの論文種別を更新」** を押すと、一覧の書誌情報をまとめて取得できます。明示的なタイトルから種別を推定した場合は、その根拠を種別欄に表示します。対象を1〜5本選び、**「選択した論文の見積もりを準備」** を押します。この時点ではPDFを外部送信しません。手動PDF/JSONが取り込み待ちに残っていれば、先に整理してください。
5. 送信のチェックを入れ、**「確認した対象をBatchへ送信」** を押します。既存の `gpt-6.1-sol` / medium / high / fulltext-v4 を使い、最大出力は通常32,000、長いガイドライン等は48,000トークンです。1論文につき1 Batchで記録します。
6. 担当Macのアプリが送信済みBatchを起動時・起動中に照合し、完了したJSONを回収します。すぐに照合する場合は **「状況確認・JSON回収」** を押せます。アプリ終了中も送信済みのBatchはAPI側で進み、次の起動時に元の台帳から再開します。
7. 検証を通ったJSONは `papers/PMID_番号/files/内容ハッシュ/PMID_番号_master.json` へ保存し、**PNG作成待ち** に更新します。テーマ別JSONとWeb用依頼文も準備します。以後のPNG作成・内容確認は手動です。確認したPNGは段階5のボタン、または手動でNotionへ登録します。

回収直後のメッセージには、今回終了を確認したBatchについて、APIが返したトークン使用量をBatch単価で換算した費用概算と、費用未確定の件数を表示します。JSONを自動保存できなかった場合も、費用を計算できた分は合計に含みます。論文ごとの費用は処理履歴で確認できます。

料金は残高確認24時間以内、残高期限まで50時間以上、期間$20・1処理版$4までという既存の制限を使います。予約見積は請求額やプロバイダー側の強制上限ではありません。ローカルの概算が272,000トークンを超えるPDFも、選んだグループの「実測待ち」に入ります。表示額は通常料金域での最大予約見積です。一度の送信確認で該当するPDFの入力を順に計測し、実測と出力枠から算出した額を予約できた論文をBatchに送ります。実測が272,000を超えた論文は処理履歴にWebで全文JSONを作るための依頼文とPDFを表示し、ほかの論文の送信を続けます。旧版で保留された論文は **「前回の対象をまとめて再見積もり」** から一括で準備できます。

- **二重送信防止**：Batch作成前に送信意図をローカル台帳へ記録します。応答不明時は再送せず、回収操作でBatch一覧と照合します。送信履歴のある同じPDFは新規送信候補から外します。Batch作成前に失敗したと確認できた場合は、明示的な再選択で1回再試行できます。未確定費用は予約を保持します。
- **失敗したBatchの再試行（2026-11-14追加）**：アプリを再起動し、担当Macで「状況確認・JSON回収」を押してから、下の処理履歴を開きます。HTTP 500/502/503/504、429の一時的なレート制限、明示的な `batch_expired` が保存済みの終了結果から確認できるときだけ **「再試行の見積もりを確認」** が表示されます。PMID・原因・再試行回数・過去の使用/予約額・今回の追加見積・累計を確認し、チェックを入れて **「確認した1件を再送（最大1回）」** を押します。
  - 同じ原本・処理版で **再試行1回（初回を含め計2回）・追加見積$1以内**。過去の使用・未確定予約を含め **累計$4・期間$20・確認済み残高** の制限も適用します。再送は自動実行しません。金額はアプリ内の送信制限で、プロバイダー請求額の保証ではありません。
  - 元の試行・エラー応答・費用予約は変更せず、新しい試行を追加します。再試行時の送信応答が不明なら予約を保持し、回収ボタンで照合します。送信前の中断・アップロード失敗も新しい試行を予約した時点で回数に含め、3回目は送信しません。
  - 結果欠落・重複・送信結果不明・JSON検証エラー・残高不足等は対象外です。PDFや記録の変更、手動JSONの取り込み、未整理の入力がある場合も送信前に停止します。残高確認が24時間以上前なら予算設定を更新して見積もりを準備し直します。
- **手動ルートとの合流**：API待ちの間にも手動JSONを保存できます。回収時に手動JSON、PDF差し替え、新しい記録、同じ論文またはPMIDを特定できない未整理のPDF・JSONがあれば、API結果は `API_JSON/results/処理版ID/` に保管し、現在の工程を変更しません。別のPMIDと特定できる入力は回収を妨げません。「状況確認・JSON回収」は保管済み候補も再確認し、送信時の原本と工程が一致し保留理由が解消していれば、自動で取り込みます。手動で採用する場合は、取り込み待ちへコピーして整理します。
- **検証失敗**：Schema、PMID、原本ハッシュ、既知の論文名、出力完了状態を検証します。形式は正しくても章参照・推奨割り当て等に不整合があるJSONは、OneDriveにも保存して「生成済み・構造確認待ち」にします。手動修正で先へ進めます。未完了、対応不一致、不正形式、結果欠落・重複は自動採用せず、元の応答を担当Macの台帳に残します。自動再生成はしません。
- **担当Macの記録**：APIキーとSQLiteジョブ・予算台帳はGit管理外のローカル `.env` / `output/json_batch/共通フォルダ識別子/`、共有進捗はOneDriveの `API_JSON/status.json`、担当は `API_JSON/owner.json` に保存します。論文工程の正本は従来の `papers/.../records` のままです。ジョブ台帳は旧 `.paper_pipeline` と分離し、旧ジョブを勝手に回収・再送しません。旧ジョブの費用は今回の残高設定へ反映してください。
- **台帳の保管**：`output/json_batch`、`output/manual_settings.json` はアプリ終了中にローカルでバックアップしてください。台帳や担当設定を削除してもAPI側のジョブは取り消せません。担当設定の同期競合・元台帳の欠落・別Macからの操作は停止します。担当変更や移設は元の台帳を保全してから別途行います。OneDriveは分散ロックではないため、未同期の複数Macで同時に初期設定しないでください。

公式仕様・単価は2026-11-13に [Batch API](https://developers.openai.com/api/docs/guides/batch) と [Pricing](https://developers.openai.com/api/docs/pricing) を確認しました。実装では既存のBatch単価（入力$1・出力$5／100万トークン、キャッシュ等は別計算）を維持しています。

## PNGを確認してNotionへ登録する（段階5）

1. アプリを再起動し、手動作成した全テーマのPNGをOneDriveへ保存して取り込みます。**「PNG確認・登録待ち」** の論文で「画像と固定情報を照合」を開き、各テーマを承認します。複数テーマの一部が作成待ちの間も、届いた画像から照合できます。
2. 工程4または論文一覧の **「PNG確認・Notion登録」** を押し、1〜5本を選んで **「選択した論文の登録内容を確認」** を押します。Notionの登録先・既存ページを読み取り、PNGのプレビューを表示します。まだアップロードはしません。
3. 各PNGを原文・JSONと照合し、画像ごとの確認欄にチェックします。必要なら **「PNGを原寸で開く」** で確認します。確認者・確認内容を入力し、表示された登録先への登録確認にチェックします。
4. **「確認した論文をNotionへ登録・再開」** を押します。既存ページが一意に見つかればそこへ追加し、なければ1論文につき1ページを作成します。ページ内にテーマごとの領域を設け、本文・テーマJSON・Master JSON・PNGを保存します。`Graphic Image`（files型）がある場合は、承認済みの全テーマのPNGを既存画像を保持して追加します。PDF原本はOneDriveに保持します。
5. 全テーマの登録と添付を再取得して確認した論文だけ、OneDriveの工程を **「登録完了」** に更新します。確認者・確認内容・ファイルの版・登録ページを記録し、結果欄からNotionを開けます。画像や記録が途中で変わった場合は「Notion登録済み・工程未反映」とし、新しい版を勝手に完了扱いにしません。

接続には担当Macの `.env` にある `NOTION_TOKEN`・`NOTION_DATABASE_ID` を使います。環境変数があれば優先します。複数データソースがある場合は `NOTION_DATA_SOURCE_ID` も必要です。既存の設定をそのまま使えます。登録先をNotion接続に共有し、読み取り・挿入・更新を許可してください。`PMID` と `Automation ID` はrich_text型（Notionのテキスト型）が必要です。DB構造や権限をアプリが変更することはありません。

最初に登録内容を確認したMacをNotion担当にします。JSON Batchの担当とは独立しており、OpenAIキー・予算設定は不要です。初回設定は1台で行い、OneDriveの同期が終わってから他のMacを開いてください。担当Mac以外でもファイル閲覧・手動作業は継続できます。

- **複数PNG・途中再開（2026-11-14修正）**：Graphic Imageは画像の実体を照合し、不足分だけ追加・再取得確認します。既存の手動画像、カバー、本文、Human Checkedを保持します。登録済みテーマも照合するため、旧版で1枚だけだった処理の再開時にも補完します。添付名は100文字以内に収め、長いテーマIDでもHTTP 400にならないようにしました。明確な添付検証エラーは修正後の明示的な再開を許可し、通信結果が不明な場合は従来どおり先に照合します。
- **重複防止**：Automation ID・PMID・正規化したDOI・記録済みページIDを照合します。候補が複数、識別が矛盾、アーカイブ・移動・ゴミ箱の記録がある場合は、新規作成せず停止します。識別項目のない手動ページは照合できないため、登録前にPMIDまたはDOIを記入してください。既存のAutomation IDも照合後に引き継ぎます。
- **中断時**：同じ論文を選び直し、PNGと登録内容を再確認して同じボタンで再開します。作成・追記・添付の前に送信意図を保存し、応答が失われてもページ・領域・添付を照合します。未確定の結果が見つからない場合は、再送して重複させず確認待ちにします。結果不明の旧版を放置して新しい版からページを作成することも止めます。
- **既存内容と確認**：既存の本文・臨床項目・選択済み画像を上書きせず、この版の領域を追加します。新規ページの `Human Checked` はオフのままです。PNG確認と、精読全体の医学的な確認は区別します。既存ページの `Human Checked` は変更しません。本文や添付が後から変更・削除され、保存結果を確認できない場合は完了にしません。
- **添付上限**：接続先の上限とsingle_partの20MiB上限の小さい方を使い、上限超過は登録前に停止します。PNGを勝手に縮小せず、外部の公開URLへも置きません。2026-11-13の実接続の読み取り確認では上限5MiBでした。
- **保管**：NotionトークンとSQLite登録台帳は担当Mac内の `.env` / `output/notion_sync/共通フォルダ識別子/`、共有の担当設定・結果はOneDriveの `NOTION/owner.json`・`NOTION/status.json` に保存します。キー・SQLiteをOneDriveやGitへ置きません。アプリ終了中にローカル台帳と `output/manual_settings.json` をバックアップしてください。元台帳の欠落・担当の競合・登録先の変更があれば停止します。担当変更や台帳移設は記録を保全してから別途行います。

**APIを使わず手動登録する経路も残しています。** 自分でNotionへアップロードした場合は、これまでどおり「確認・登録の記録」で完了を記録してください。PNG生成APIは接続していません。Mac停止中に新規登録は進まず、実行中は担当Macのアプリを開いたままにします。OneDriveへのクラウド同期完了は別途確認してください。

実装は既存の `paper_pipeline/notion.py` のページ照合・アップロード・送信意図記録・再取得確認を再利用しています。公式仕様は [データソース照会](https://developers.notion.com/reference/query-a-data-source)、[ファイルアップロード](https://developers.notion.com/reference/create-file)、[リクエスト制限](https://developers.notion.com/reference/request-limits) を参照しています。

`files/`・`records/`は編集せず、変更するファイルを`受け渡し/`へ保存します。PDFやJSONの新しい候補を同時に複数置いた場合は、自動で選ばず要確認にします。採用する候補1つを残し、他は共有フォルダ外の作業用フォルダへ移してください。取り込み済みの入力ファイルは自動削除しません。

共有側ではSQLiteもMac内のシンボリックリンクも使いません。各更新は固有名のファイルに追記します。同じPMIDを自宅と職場で並行更新すると、両方の版を残し「要確認・競合」に表示します。時刻だけで片方を上書きしません。両方のファイル・メモを確認し、採用する記録を明示して解決できます。

## iPhone・iPad、Macが停止中の場合

OneDriveの `papers/PMID_番号/files/` からPDF・JSON・PNG・依頼文を開き、Webでの作業に利用します。生成したファイルは `00_取り込み待ち/PMID_番号/` へ保存し、次にMacで「取り込み・整理」を実行します。既存の `受け渡し/JSON` または `受け渡し/PNG` に保存した場合は、Macアプリの次の確認で取り込みます。
進捗は `状況/端末ID/状況.txt` で確認できます。複数端末のファイルがある場合は本文の端末名・記録日時を確認します。HTMLのプレビューやリンク操作は端末・アプリに依存するため、iOSではTXTと実ファイルを基本にします。

**MacBook Airの常時起動は不要です。ただしMacを閉じる前にOneDriveへの同期が終わっている必要があります。**
自宅Macが停止中でも、職場Macのアプリが記録できます。両方のMacが停止中にiPhone/iPadで保存したファイルはOneDriveで共有されますが、共通取り込み待ちの工程記録は次にどちらかのMacで「取り込み・整理」を実行したときに更新します。整理前でも、アップロード済みの実ファイルは閲覧できます。

表示するのは「各Macが最後に記録した状態」であり、クラウド同期完了の保証ではありません。

### iPhoneで状況画面を見る

今までと同じ [PubMed 進捗](https://pubmed-progress-thama.fairkayak3.chatgpt.site) を開き、同じChatGPTアカウントでサインインします。現在のMacアプリと同じ6区分の件数・確認端末・最終確認時刻を表示します。サイトの旧ラベル「手動登録完了」には、今回のNotionボタンから登録した完了分も含まれます。

状況共有を設定したMacでは、起動時・手動更新・操作に伴う更新時に件数を共有します。他端末で保存したファイルは、Macの「保存状況を確認」で確認してください。iPhone側は約30秒ごとに最後の共有内容を読み直し、「いま更新する」でも再取得できます。共通取り込み待ちのファイルは「取り込み・整理」の実行後に反映します。`.command` 単独実行でも、状況共有が設定済みのMacでは整理後に件数を1回共有します。未設定・共有失敗でもOneDriveの状況ファイルは保存します。Mac終了・スリープ・通信切断中も最後に共有した状況と最終確認日時を表示します。定期共有ではないため、経過時間だけでは警告を出しません。iPhone側の再読み込みはMacの処理やOneDriveの読み取りを実行しません。

共有するのは件数・端末名・確認時刻だけです。論文本文・PMID・ファイル・メモはサイトへ送りません。共有用の認証設定は各Mac内のGit管理外 `.remote_status/config.json` を使い、OneDriveへ置きません。このMacの既存設定を継続利用します。他のMacでも直接共有するには、そのMacにも専用の認証設定が必要です。未設定の場合はMac画面に「状況共有が未設定」と表示します。

進捗サイトは閲覧用です。JSONの回収はAPI担当Macのアプリが行います。

Macで共有フォルダを「このデバイス上で常に保持」に設定すると、作業ファイルをオフラインでも使えます。[Microsoftの説明](https://support.microsoft.com/en-us/onedrive/save-disk-space-with-onedrive-files-on-demand-for-mac)
iOSの「ファイル」アプリにもOneDriveを追加できます。[Appleの説明](https://support.apple.com/en-us/102238)

## 共通の保存・工程更新

段階5の確認後Notion登録まで接続済みです。`intake.organize`、`pdf_download.download_selected`、`json_batch.collect` は同じ `Workspace.import_file` を使い、共通の検証・履歴・工程へ合流します。`json_batch` は既存 `batches.Batches` の送信・回収・予算予約・不明送信の照合を再利用し、画像・Notionの処理へは進みません。従来のPNG一括登録では `notion_sync` の選択・PNG確認・登録操作を使い、全テーマの登録確認後に共通Workspaceへ完了記録を追加します。
